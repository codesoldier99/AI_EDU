# 讲义：数据泄漏——比模型选错更致命的错误

## 1. 什么是数据泄漏

模型在训练阶段接触到了它在真实预测时不可能拥有的信息。
后果是离线指标极好、上线即崩，而且**排查代价极高**，因为代码通常不报错。

## 2. 四种最常见的形态

| 形态 | 典型写法 | 后果 |
|---|---|---|
| 预处理泄漏 | 先对全量数据 `scaler.fit_transform`，再 `train_test_split` | 测试集的均值方差进入了训练 |
| 标签泄漏 | 特征里混入了由标签派生的字段（如"是否已理赔"） | 指标接近满分，上线无效 |
| 时间穿越 | 随机划分时序数据，用未来预测过去 | 离线 AUC 虚高 |
| 分组穿越 | 同一台设备/同一个人的样本同时落在训练与测试 | 学到的是身份而非规律 |

## 3. 正确顺序

```
split → fit(仅训练集) → transform(训练集/验证集/测试集) → 训练 → 只在最后评估一次测试集
```

任何"先处理再划分"的写法都要停下来问一句：这一步用到了全量数据吗？

## 4. 与测试集调参的关系

在测试集上挑阈值、挑模型、挑特征，本质上是另一种泄漏——
它泄漏的不是数据而是**选择自由度**。正确做法是验证集或嵌套交叉验证，
测试集只在最后使用一次，用完即弃。

## 5. 自查清单

- 数据划分是不是全流程的第一步？
- 每一个 `fit` 是不是只见过训练集？
- 时序数据是否按时间切分？
- 同一实体的样本是否被 group 约束在同一侧？
- 最终报告的指标，测试集被用过几次？
