# 知识点标注规范（教师用）

本文给一线教师看，不需要任何编程基础。
标注结果直接写进 `data/seed/course_ml.yaml`，跑一次 `make seed` 即可入库。

---

## 一、粒度准则：能独立命题、能独立判定会不会

这是唯一的判定标准。举例：

| 写法 | 判定 | 原因 |
|---|---|---|
| 「机器学习」 | ✗ 太粗 | 无法出一道题判定"会不会机器学习" |
| 「反向传播算法」 | ✓ | 可以出题：写出两层网络所有参数的梯度 |
| 「反向传播中 ReLU 那一层导数的写法」 | ✗ 太细 | 不构成独立的能力单元，属于上一条的一部分 |
| 「链式法则」 | ✓ | 可以独立命题，且是多个知识点的共同前置 |

单课程建议 **300–500 个**知识点。当前试点课程《机器学习原理与应用》标了 183 个，
属于偏粗的一版，可在使用中细化。

> 待拍板事项之一：一门课究竟拆成 300 个还是 500 个？请一线教师凭经验给意见。

---

## 二、依赖边只标强依赖

判定句式：**"学 B 之前必须先会 A"**。

- ✓ 学「反向传播」之前必须先会「链式法则」→ 标 prereq
- ✗ 学「随机森林」之前"最好"了解「决策树剪枝」→ 这是弱相关，不标或标 related

**标错的代价不对称**：漏标一条强依赖，根因回溯会停在半路；
多标一条弱依赖，系统会把学生挡在一个其实不必先学的点上。
所以宁可漏标，不要滥标。

依赖图必须是 DAG（无环）。`make seed` 会做环检测，成环直接拒绝入库。

---

## 三、能力模块：每个知识点挂 1–3 个

| 代码 | 名称 |
|---|---|
| M1 | 数学与建模基础 |
| M2 | 编程与工程实现 |
| M3 | 算法设计与分析 |
| M4 | 数据处理与特征工程 |
| M5 | 模型训练与调优 |
| M6 | 系统集成与部署 |
| M7 | 工程质量与协作 |
| M8 | 技术表达与伦理素养 |

挂多了等于没挂——如果一个知识点挂了 5 个模块，说明它太粗，应当拆开。

---

## 四、怎么写

打开 `data/seed/course_ml.yaml`，按行填写，字段用 `|` 分隔：

```
代码 | 名称 | 类型 | 难度 | 能力模块 | 前置知识点 | 一句话说明
```

实例：

```yaml
  - name: 第10章 神经网络与反向传播
    kps:
      - ML-10-05 | 反向传播算法 | method | 0.8 | M1,M3 | ML-10-04,ML-02-08 | 能逐层推导梯度——最常见的卡点
```

- **类型** ∈ `concept`（概念）/ `method`（方法）/ `skill`（技能）/ `tool`（工具）。
  类型会影响追问方式的选择：方法与技能类优先用"条件变更""反例质疑"。
- **难度** 0–1，凭教学经验给。它只影响演示数据的生成与展示，不参与掌握度计算。
- **一句话说明** 会进入检索，写得具体一点对系统有实际帮助：
  写"理解反向传播"没用，写"能逐层推导梯度，最常见的错误是漏掉激活函数的导数"有用。

改完执行：

```bash
make seed        # 环检测 + 入库；有问题会明确报出来
```

## 五、任务-知识点映射（★ 最重要，也最容易被低估）

这张表是**拉取式的前提**，没有它系统只能退回按课程顺序推送。
它也是学分认定与能力追溯的依据，因此**必须由导师标注，不能交给大模型自动生成**
（大模型可以给候选清单，教师确认）。

打开 `data/seed/projects.yaml`：

```
任务代码 | 任务名称 | 父任务 | 里程碑 | 必需知识点 | 有帮助的知识点
```

```yaml
      - T-AGV-3 | 障碍物识别模型 |  | 1 | ML-12-02,ML-12-03,ML-10-05 | ML-12-04
```

- **必需（required）**：不会这个就做不下去 → 进入缺口计算
- **有帮助（helpful）**：会了更好 → 不进入缺口，只在任务详情里展示

一个叶子任务挂几个知识点合适？经验值是 **3–6 个**。
挂太多说明任务没拆够，挂太少说明知识点标得太粗。

> 待拍板事项之一：任务-知识点映射的标注粒度。首批只做 2 个项目验证粒度是否可用。

## 六、错误模式的确认

系统会自动采集学生的错误实例，并做粗聚类。教师需要做的是**确认或修正**：

1. 打开教师端「错误模式库」标签页
2. 看某条模式的描述与原始样本是否吻合
3. 吻合就点「确认」，不吻合可以改描述与归因根因

只有教师确认过的模式，才会被用来向学生解释。

这是整个系统里最有价值、也最需要教师投入的一件事：
一位从教二十年的教师最不可替代的能力，是他知道学生会在哪里犯错、
错的背后通常是哪个概念没通。这份经验从未被记录，教师退休即消失。
每确认一条，就把一点个人记忆变成了学院资产。
