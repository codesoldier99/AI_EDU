# 15 分钟演示脚本（评审会用）

准备：

```bash
make setup && make dev      # → http://127.0.0.1:8900/
```

演示全程**不需要联网、不需要 API Key**。这一点本身就是第一个论点。

---

## 0'00 开场：一句话与一个反问（1 分钟）

> 本方案的核心主张：把学生的真实状态沉淀下来，把教师的经验积累起来，
> 把大模型放在它该在的位置上。

指着右上角的徽章：**「大模型：离线降级」**。

> 现在系统里没有任何大模型在跑。接下来所有的判断——谁卡在哪、根因是什么、
> 该推哪个知识点——都会照常给出。因为这些判断本来就不是模型做的。
> 模型只负责把话说漂亮，而这一部分现在被降级成了模板。

---

## 1'00 断裂一：看不见 → 班级诊断（4 分钟）

打开【班级诊断】。

**先看热力图**：183 个知识点按掌握度升序排列，一眼能看到红色区域在哪。
点任意一格可以下钻到知识点详情。

**重点在 Top 3 待攻克点**。请评审注意三件事：

1. 排序不是按错误率，而是 **低掌握 × 挡路度**。
   一个所有人都错、但不挡任何路的边缘知识点，不该占下节课的时间。
2. 每一条都有**根因回溯**：系统会告诉你"真正卡住的是链式法则，不是反向传播"。
   这一步靠的是知识图谱的显式依赖结构，纯大模型方案给不出可核对的依据。
3. 每一条都可以**一键否决**。系统给的是建议不是指令，
   否决记录用于改进系统，**不用于评价教师**。

**再看右下角两块**：

- 需个别介入的学生名单（证据不足的会显示"数据不足，仅供参考"）
- 追问降级热点：系统被迫给出提示的地方，就是该重讲的地方

> 这就是接上第一处断裂：教师第一次能在课后当天看到全班卡在哪里，
> 而且看到的是病根，不是症状。

---

## 5'00 断裂二：动不了 → 拉取式（4 分钟）

切换身份到**学生**，打开【拉取式任务】。

选择项目「园区自主配送 AGV」，点任务「障碍物识别模型」的**算缺口**：

```
所需 3  已掌握 0  缺口 3
本次只推这些（拉取式）：
  反向传播算法        掌握度 0.214   挡路度 14.0
  卷积操作与局部感受野   掌握度 0.000   挡路度 2.5
```

请评审注意：

> 传统智能教学系统按依赖顺序排课，学生"先学半年螺丝刀再拆引擎"。
> 这里反过来：学生手上有一个真实任务，系统只回答一个问题——
> **要做这个，你还缺什么**，而且一次只给最挡路的一两个。学完立刻用回项目。
>
> 知识图谱的角色因此变了：它不再是教学顺序表，而是按需检索的索引。

顺带指出一处**故意的缺失**：整个界面没有"课程进度百分比"。
过程完全个体化之后，这个概念本身就不成立了。出口仍是统一的 30/70 考核。

---

## 9'00 引导：不给答案，但也不放任挫败（2 分钟）

点缺口卡片上的【开始引导追问】。

第一轮系统会说：**"你已经掌握了 XX，就从这里出发——"**
这个切入点是算出来的：从学生已掌握的最近前置知识点切入，
而不是在他完全不懂的层面上提问。

连续点三次【我卡住了】，观察顶部标签从「未降级」变成「已降级到 L1 / L2」。

> 降级是硬约束：关键提示 → 解题框架 → 完整解析并标记教师介入。
> 每一次降级都写进事件流，回到教师端就成了刚才看到的降级热点。
>
> 但请注意降级的目的：**防止挫败感摧毁动机，不是为了让学生轻松**。
> 有证据表明，不加限制的 AI 辅助会使学生独立考试成绩下降约 17%，
> 引导式提示则显著更优。所以我们把"不给答案"写成了代码里的硬约束，
> 而不是提示词里的一句话。

---

## 11'00 断裂三：接不上 → 代码审查（2 分钟）

切回教师身份，打开【代码审查】，在底部粘贴一段有问题的脚本（`scripts/demo.py` 里有现成的），
点【静态分析 + 模型评审】。

看结果表格的**「知识点映射」**一列：

- 大部分发现显示「无可靠映射」——裸 except、函数过长，说明工程素养，
  不说明某个知识点没掌握。
- 只有少数几条挂上了知识点：比如「在划分数据集之前 fit 了预处理器」→ 数据泄漏。

点【采纳】，观察状态变为「已采纳并回写 1 个知识点」。

> 这是把工程问题翻回知识判断的唯一通道，也是项目与课程不再是两张皮的关键。
> 原则是**宁缺毋滥**：映射不可靠就不回写。
> 而且必须教师采纳之后才回写，权重只有正式测验的一半。

---

## 13'00 收尾：为什么它能活十年（2 分钟）

打开【可审计性】标签页。

**第一块**：`make replay` 的在线版本——从事件流完整重算掌握度与参与度，逐条比对。

> 掌握度不是模型说的，是事件算出来的。任何人都可以拿走事件流自己重算一遍。
> 这是系统可被第三方核查的基础。

**第二块**：可替换 / 可积累的分界表。

| 大模型 | 可替换 | 现在是"离线降级" |
| 知识图谱 | 可积累 | 183 节点 |
| 学生状态历史 | 可积累 | 60 名学生 |

> 架构的一条铁律：任何可积累的东西，都不得依赖任何可替换的东西的内部实现。
>
> 今天用这个模型，明年出了更强的换掉即可——系统能力自动提升，
> 此前积累的一切不受影响。当前市面上多数教学产品把两者混在一起，
> 本质上是把系统的命运绑在某一代模型上。这是它们做不长的根本原因。

最后一句：

> 三届学生之后，这个系统能回答一个新教师问不出、老教师答得出的问题：
> **这个知识点，学生通常错在哪。**
> 那时它就不再是一个工具，而是学院的资产。

## 命令行版本（技术评审时用）

```bash
make check                          # 架构铁律静态检查
make test                           # 79 个用例
make replay                         # 全班事件流重算校验
make gap STUDENT=1 TASK=T-AGV-3     # 缺口与挡路度，纯确定性输出
```

配一个真实模型再演示一遍，对比结论是否改变（不会改变，只是措辞更自然）：

```bash
LLM_BASE_URL=... LLM_API_KEY=... make dev
```
