# 汇报与演示预案

配套材料：`docs/slides/院长实验班AI教学系统_汇报.pptx`（32 页，另有同名 PDF）

全程**不需要联网、不需要 API Key**。这一点本身就是第一个论点。

---

## 一、会前 10 分钟：把环境准备好

开**两个终端**，都在项目目录下。

**终端 A —— 主系统**

```bash
cd AI_EDU
python3 aiedu.py setup          # 若之前已跑过，可跳过；约 1–2 分钟
python3 aiedu.py dev            # 保持运行
```

**终端 B —— 留着敲命令行演示**

```bash
cd AI_EDU
python3 aiedu.py check          # 架构铁律自检，应输出 OK
python3 aiedu.py replay         # 应输出 "重算校验：60/60 一致"
```

**浏览器**：开三个标签页，提前登录好，避免现场等待。

| 标签 | 地址 | 身份（右上角下拉框） |
|---|---|---|
| 1 | http://127.0.0.1:8900/ | 教师 · 张导师（实验班A） |
| 2 | 同上 | 学生 · 第一位同学 |
| 3 | 同上 | 教师（停在「可审计性」页） |

**投影设置**：浏览器 `Ctrl +` 放大到 125%；页面右上角有主题切换（◐），会议室灯亮时用浅色。

**会前自检清单**

- [ ] 首页右上角显示「大模型：离线降级」——这是演示四的伏笔，别急着接模型
- [ ] 教师端【班级诊断】能打开，热力图有颜色
- [ ] 学生端【拉取式任务】→ 任意任务「算缺口」有结果
- [ ] 终端 B 的 `replay` 输出 60/60 一致
- [ ] PPT 已打开，停在封面

## 三、四段演示，逐步照做

### 演示一 · 接上「看不见」（4 分钟）

**在哪**：标签 1，教师端 →【班级诊断】

**照这个顺序指**：

1. 顶部三张卡片：主动使用率、待攻克知识点数、降级次数。
2. 中间的**热力图**：183 个知识点按掌握度升序，红色区域一眼可见。点一格下钻。
3. **Top 3 待攻克点**——这是本页的重点，请评审看三件事：
   - 排序不是按错误率，而是 **低掌握度 × 挡路度**
   - 每一条都有**根因回溯**：「真正卡住的是链式法则，不是反向传播」
   - 每一条旁边都有【否决】按钮
4. 下方：需个别介入的学生名单（证据不足的会标「数据不足，仅供参考」）、降级热点。

**要说的话**

> 这就是接上第一处断裂：教师第一次能在课后当天看到全班卡在哪里，
> 而且看到的是病根，不是症状。
>
> 请注意排序规则——一个所有人都错、但不挡任何路的边缘知识点，
> 不该占用下节课的时间。

**如果有人问「根因怎么算的」**：切 PPT 第 12 页，或直接在界面点那个知识点，
看它的前置与后续关系。

---

### 演示二 · 接上「动不了」（4 分钟）

**在哪**：标签 2，学生端 →【拉取式任务】

1. 项目选「园区自主配送 AGV」。
2. 点任务「障碍物识别模型」右侧的【算缺口】。
3. 右栏出现：所需 3 / 已掌握 0 / 缺口 3，以及「本次只推这些」两张卡片。
4. 往下滚，看完整缺口表里的**挡路度**与**前置卡点**两列。

**要说的话**

> 传统智能教学系统按依赖顺序排课，学生"先学半年螺丝刀再拆引擎"。
> 这里反过来：学生手上有一个真实任务，系统只回答一个问题——
> **要做这个，你还缺什么**，而且一次只给最挡路的一两个。学完立刻用回项目。
>
> 知识图谱的角色因此变了：它不再是教学顺序表，而是按需检索的索引。

**顺带指出一处故意的缺失**（很多人会注意到）：

> 整个界面找不到"课程进度百分比"。过程完全个体化之后，这个概念本身就不成立了。
> 出口仍是统一的 30/70 考核——过程个体化，出口有门槛。

**命令行版本**（技术同事在场时更有说服力，终端 B）：

```bash
python3 aiedu.py gap 1 T-AGV-3
```

### 演示三 · 引导追问与降级（3 分钟）

**在哪**：接上一步，点缺口卡片上的【开始引导追问】

1. 看第一句：「你已经掌握了 ××，就从这里出发——」，指出这个切入点是算出来的。
2. 连续点三次【我卡住了】。
3. 观察顶部标签：「未降级（不会直接给答案）」→「已降级到 L1」→「L2」。
4. 切回标签 1 教师端【班级诊断】，刷新，看**降级热点**多了一条。

**要说的话**

> 追问的起点、深度、方式三件事都由学生状态决定，不交给大模型自由发挥。
>
> 降级是硬约束：关键提示 → 解题框架 → 完整解析并标记教师介入。
> 每一次降级都写进事件流，回到教师端就成了刚才看到的降级热点。
>
> 但请注意降级的目的：**防止挫败感摧毁动机，不是为了让学生轻松**。
> 有证据表明，不加限制的 AI 辅助会使学生独立考试成绩下降约 17%，
> 引导式提示则显著更优。所以我们把"不给答案"写成了代码里的硬约束，
> 而不是提示词里的一句话。

### 演示四 · 把大模型接上去（4 分钟）★ 全场最关键的一段

**准备**：演示一的班级诊断页面**先截个图或不要关**，一会儿要对比。

**第 1 步**，终端 B 起假底座（现场没网络也能演）：

```bash
python3 aiedu.py mock-llm --port 8910
```

**第 2 步**，终端 A 按 Ctrl-C 停掉服务，改用带模型配置的方式重启：

```bash
LLM_BASE_URL=http://127.0.0.1:8910/v1 LLM_API_KEY=demo LLM_MODEL=mock-qwen \
python3 aiedu.py dev
```

> 若现场有真实 Key（通义千问 / DeepSeek），把三个变量换成真的即可，效果一样。

**第 3 步**，刷新浏览器：

- 右上角徽章从「大模型：离线降级」变成模型名
- 回到【班级诊断】：**Top3、根因、名单、置信度——一个字都没变**
- 只有最上面那段「诊断结论」的措辞变自然了
- 打开【教师简报 / 学分映射】页底部的「大模型调用与成本分账」，能看到刚才那次调用的模型名与 token 数

**要说的话**

> 这是本方案唯一真正重要的技术判断的现场证明。
>
> 大模型是嘴，不是脑。换掉嘴，说的话变好听了，判断一个字都没变——
> 因为这些判断本来就不是模型做的。
>
> 含义是：今天用这个模型，明年出了更强的换掉即可，系统能力自动提升，
> 此前积累的知识图谱、错误模式库、学生状态历史，一点都不受影响。
>
> 市面上多数教学产品把两者混在一起，本质上是把系统的命运绑在某一代模型上。

**这条结论已经写成自动化测试**，终端 B 可以当场跑：

```bash
cd tests && python3 -m unittest test_llm_switch -v
```

### 收尾 · 可审计性（2 分钟）

**在哪**：标签 3，【可审计性】

- 「事件流重算校验」显示 ✓ 重算一致
- 「可替换 / 可积累的分界」表

**要说的话**

> 掌握度不是模型说的，是事件算出来的。事件流只追加，数据库层面禁止修改和删除。
> 任何人都可以拿走事件流自己重算一遍。这是系统可被第三方核查的基础。

终端 B 补一刀：

```bash
python3 aiedu.py replay        # 重算校验：60/60 一致
python3 aiedu.py check         # 架构铁律自检，OK
```

## 四、演示出问题时的退路

| 状况 | 处理 |
|---|---|
| 页面打不开 / 白屏 | 终端 A 是否还在跑；换 `python3 aiedu.py dev --port 8901` |
| 数据看起来不对 | `python3 aiedu.py reset && python3 aiedu.py setup`，约 2 分钟 |
| 演示四接不上模型 | 直接讲结论 + 跑那条单元测试；测试通过同样有说服力 |
| 时间不够 | 只留演示一和演示四。演示一回答"有没有用"，演示四回答"能不能长久" |
| 完全跑不起来 | PPT 第 14、18 页本身就带着实测输出与对比结论，可以纯讲 |

## 五、可能被问到的问题（先想好）

**「这跟直接用大模型问答有什么区别？」**
> 区别在于状态由谁维护。直接问大模型，它每次都在猜；同一个学生换个上下文，
> 判断就变了，教师无法采信，也无法积累。我们把判断交给算法，把表达交给模型。
> 刚才演示四就是这个区别的现场证明。

**「知识图谱标注工作量多大？受得了吗？」**
> 试点课程目前 183 个知识点，是一个人两三天的工作量，而且是一次性的——
> 一门课建好永久复用。做法是大模型预抽取、教师审核。
> 知识点标注本身也适合作为学生的入门实战任务，接口清晰、可独立验收。

**「学生会用吗？」**
> 这是最大的风险，我在 PPT 第 30 页专门列了。国外同类产品的教训是只有约 15%
> 的学生经常使用——最大难题在行为不在算法。
> 我们的对策有三条：教师侧先行；把使用率观测提前到第一阶段（不是等系统建完
> 才发现没人用）；追问入口嵌在作业与项目流程里，不做独立 App。
> 界面上那个"主动使用率"就是为此存在的。

**「会不会让学生更依赖 AI，越来越不会自己想？」**
> 这正是我们最警惕的。有证据表明不加限制的 AI 辅助会使独立考试成绩下降约 17%。
> 所以系统里有三条硬约束：不给答案（除非触发降级且留痕）；
> 不以当场正确率作为任何优化目标；不为提升体验而降低难度。
> 激励只给"坚持"类行为，白名单在代码里，传正确率类的进去直接报错。

**「系统会不会拿来考核我们老师？」**
> 不会，而且这一条是写进架构约束的。系统不生成、不留存任何针对教师的评价性数据，
> 数据库表结构里有一条自动检查，出现这类字段测试就不通过。
> 界面上那个"教师打开诊断报告的次数"是对**系统**是否被真正使用的观测，
> 接口返回值里也写明了不进入任何教师考核。

**「结论不准怎么办？」**
> 数据不足时系统会明说数据不足，不做精确性伪装。所有结论都带置信度与证据条数。
> 而且一切输出都是建议，可采纳、可修改、可否决；否决记录用于改进系统。

**「和其他学院/公司的产品比，优势在哪？」**
> 一是状态与表达分离，换模型不清零；二是错误模式库——把教师"知道学生会在哪里
> 犯错"这份经验变成学院资产，这是别人拿不走的；三是拉取式，天然贴合实验班的
> 项目驱动模式。第三点别人不是做不到，是他们的课程形态不允许。

**「什么时候能用上？」**
> 教师端现在就能用——今天演示的是可运行系统，不是原型。
> 需要各位提供的是八项参数的初值（PPT 第 28 页）和试点课程的真实作业数据。
> 学生端建议等教师侧跑顺一个月之后再开放。

**「要花多少钱？」**
> 目前零成本运行：本机跑，无数据库服务、无云服务、无 API 调用。
> 接真实大模型之后按 token 计费，系统内置了按用途的成本分账（演示四里看到的那张表）。
> 也可以用校内 GPU 私有化部署国产开源模型，数据不出校。
