# OpenMAIC 研判：国内同行做到哪一步，我们吸收什么，什么不跟

> 对象：[THU-MAIC/OpenMAIC](https://github.com/THU-MAIC/OpenMAIC)
> （清华大学 MAIC 团队，Open Multi-Agent Interactive Classroom，
> 2026 年 3 月开源，MIT 协议，约 3.1 万星，论文见 JCST'26）。
> 结论：**它证实了"每个角色一个 Agent"这条路走得通；课件生成的形态可以借，
> 判定权仍然不让。**

这是继 [LearnVector 研判](learnvector-研判.md)、[DeepTutor 研判](deeptutor-研判.md)
之后的第三份。三家分别代表产业（吴恩达）、港校（港大 HKUDS）与内地顶尖高校（清华），
三条路径独立收敛出来的共同点，比任何一家的单独主张都更值得当作判断依据。

---

## 一、它到底是什么

一句话：**给一个主题或一份材料，一键生成一整门可上的课，并且用多个 AI 角色把它讲出来。**

- **多智能体课堂**：AI 教师 + AI 同学，会讲、会在白板上写、会跟学生实时讨论。
- **一键成课**：大纲 → 幻灯片 → 测验 → 互动仿真 → 项目式学习（PBL），可导出
  可编辑的 `.pptx` 或交互 `.html`。
- **Agent 工作台（v1.0.0）**：对话式建课，会话落库、可中断可续、可中途改指令；
  内置 20 个技能包，用户也能自己写。
- **深度互动模式**：3D 可视化、仿真、游戏、思维导图、在线编程——
  "学生不是看知识，是动手调实验"。
- **供应商中立**：模型、媒体、搜索、存储都可换；凭据不下发到浏览器；
  **模型路由解析不出来时显式失败，而不是猜一个厂商**。

## 二、它证实了什么

这一条对我们最重要，因为它是**独立的**证据。

| 我们已经在做的判断 | OpenMAIC 的独立印证 |
|---|---|
| 每个角色一个 Agent（本次汇报第 13 页的构想图） | 它把"AI 教师 + AI 同学"做成了产品形态，而不是停在论文里 |
| 教学技能包用 `SKILL.md`，教师写 Markdown 即扩展 | 它也用同一个 `SKILL.md` 格式，内置 20 个、支持用户自写 |
| 可替换件必须在接口后面，换模型不动业务代码 | 它的 provider-neutral 设计与"解析不出来就显式失败"是同一条规矩 |
| 课件生成应当是一条链路：大纲 → 计划 → 课件 | 它把这条链路一直做到互动仿真与 PBL，且能导出 `.pptx` |

**三个团队（清华、港大、吴恩达）在完全不同的语境下收敛到同一批原则**，
这件事本身说明这些原则大概率是对的——包括我们此前只是"觉得应该这样"的几条。

## 三、根本分歧只有一条（还是那一条）

| | OpenMAIC | 本系统 |
|---|---|---|
| 产出的是什么 | **一堂课**（内容与体验） | **一个判断**（他会了没有、还缺什么） |
| 谁做判断 | 模型（生成内容、组织课堂） | 确定性算法（BKT / 图算法 / 规则判分） |
| 错了的代价 | 这堂课不好听，换一个提示词重生成 | 写进能力档案、折算学分、进两年纵向研究基线 |
| 因此的取舍 | 灵活优先 | **可复算优先** |

这与 DeepTutor 的分歧口径完全一致：**能力面可以抄，判定权不能让。**
不是谁对谁错，是面向的场景不同——它服务的是"任何人想学任何主题"，
我们服务的是"一个学院要为 60 个学生的学分负责"。

## 四、逐条取舍

| OpenMAIC 的能力 | 判定 | 我们怎么做 |
|---|---|---|
| 大纲 → 幻灯片 → 课件的生成链路 | ✅ 已有，形态一致 | `packages/courseware`：大纲 / 教学计划 / 课件三段。**但排版由确定性代码生成，模型只写讲解词**——课件在不同机器上必须长得一样 |
| `SKILL.md` 技能包 | ✅ 已有，收窄 | `packages/skills` + `skills/*.md`。技能包**够不到"算不算掌握"**，只能影响怎么问、怎么出题；且不做远程 hub 安装 |
| 多智能体角色 | ◐ 方向一致，实现不同 | 我们的 agents 之间只传结构化消息（Pydantic model），**禁止自由对话**——自由对话的链路没法复算 |
| 供应商中立 / 可换模型 | ✅ 已有 | `packages/llm` 统一封装，无 Key 时降级为离线确定性表达器 |
| 一键生成整门课 | ❌ 不跟 | 与核心范式冲突：**知识由项目需求拉取，不由课程顺序推送**。我们不生成课程，我们回答"要做这个，还缺什么" |
| AI 同学、TTS、语音克隆、沉浸式课堂 | ❌ 现阶段不跟 | 提升的是体验，不在四个合法优化目标里（延迟后测 / 迁移任务 / 项目产出 / 主动使用率） |
| Next.js + React + TS + LangGraph + Postgres/S3 | ❌ 不跟 | 演示环境常常没有外网。我们的硬约束是"零构建、纯标准库、断网可完整演示"，这条不让步 |
| 联网抓取材料、生成图片与视频 | ❌ 不跟 | 限域调研只查院内三库，生成后还要量一次落地性；外网材料量不了 |

## 五、它有而我们没有、且值得考虑的

诚实记一笔，免得只看见自己有的：

1. **导入 `.pptx` 并保留版式**——教师手里最多的就是旧课件。我们现在只能生成，不能吃进来。
2. **深度互动（仿真 / 在线编程 / 3D）**——我们的图示是确定性 SVG，静态。
   互动仿真对"有意义的困难"是有帮助的，但要先想清楚怎么判定，否则又变成体验指标。
3. **会话落库、可中断可续、可中途改指令**——我们的追问会话还比较薄。

这三条都不是明天就要做的，记在这里是为了下次排优先级时不用重新想一遍。

## 六、一句话

**清华把"多智能体课堂"做成了能用的产品，这证明我们第 13 页那张构想图不是空想；
但它生成的是一堂课，我们要生成的是一个能被质疑、能被复算的判断——
所以能力面照抄，判定权照旧不让。**
